# S3 upload security

## Purpose

Keep files private, server-controlled and verified: clients get short-lived, narrowly signed URLs and never credentials; nothing is trusted until verified.

## When to use

Any change under `src/modules/uploads/`, `src/infrastructure/storage/`, `src/jobs/workers/upload-jobs.ts`, bucket configuration, or a new feature that stores files.

## Invariants (do not break)

1. Object keys are generated by `buildObjectKey` from purpose, server id and the extension of the **allowed content type**. No client input in keys.
2. Presigned PUT signs `content-type`, `content-length`, `if-none-match` (and `x-amz-checksum-sha256` when given); TTL `UPLOAD_URL_TTL_SECONDS` (≤ 5 min default).
3. The record is inserted (`pending`) **before** the URL is issued.
4. `/complete` checks HeadObject size/type/checksum and magic bytes (`detectContentType`) before `available`; failures move to `deleting` with a reason.
5. Only the uploader completes; reads/deletes of others require `uploads:*:any`; invisible resources return 404.
6. Deletion is soft (record kept) and object removal is asynchronous, delayed until the PUT URL expired; the sweep reconciles stuck states.
7. Script-capable types (SVG, HTML, XML) are never allowed. Non-images download with `Content-Disposition: attachment`.
8. The bucket stays private; IAM is limited to `uploads/*` Put/Get/Delete.

## Workflow — new purpose or type

1. Add to `UPLOAD_PURPOSES`/`UPLOAD_POLICY` (types + max size) in `upload-policy.ts`.
2. New type ⇒ add to `ALLOWED_CONTENT_TYPES`, `EXTENSION_BY_TYPE`, and a signature in `file-signature.ts` with unit tests (positive and look-alike negatives).
3. Validator enums update automatically from the constants; run `npm run db:migrate:dev`.
4. Update bucket CORS `AllowedHeaders` only if a new signed header is introduced.

## Workflow — when to go further

- Files > ~100 MB or unreliable mobile networks → S3 multipart upload with per-part presigned URLs and `CompleteMultipartUpload` verification; keep the lifecycle rule aborting incomplete uploads.
- Thumbnails/resizing → worker job after `available`; write derivatives under a separate prefix; never block `/complete`.
- Untrusted sharing or regulatory need → asynchronous malware scan before `available`.
- Heavy download traffic or remote sites → CloudFront + Origin Access Control + signed URLs; bucket policy allows only the distribution.

## Validation checklist

- [ ] Tests: wrong size, wrong type, signature mismatch, cross-user complete/read/delete, idempotent complete, deletion with queue down.
- [ ] `npm run smoke:upload` against the local S3 emulator (real signature semantics) passes.
- [ ] No AWS credentials or bucket URLs with credentials reach the client or logs.
- [ ] `docs/security-checklist.md` Uploads section still true.
